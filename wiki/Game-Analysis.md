# Game Analysis Skills

## game-deconstruction

`game-deconstruction` 用于学习用户自有或已授权游戏的 AI、技能、动画与渲染配置。它把工作固定为 P0–P8 白盒流程：先确认 build 与学习问题，再发现并验证目录器、解包器、结构解析器和第二验证器；随后执行只读目录化、分层定向提取、字段/引用解析、运行时补证、工程综合与发布回归。

这项技能不把录像观察或公开资料推断冒充白盒结论，也不复制专有游戏代码或美术资产。遇到加密密钥、DRM/许可证绕过、注入或写回原安装等要求时，会停止该工具路线并寻找合规的只读替代方案。

## 机制解释契约

面对“某个 Goal 怎么做、何时成立、怎么调参”之类的问题，技能要求从同一份机器种子生成 Book 与 Agent 答案，至少包含：

1. 真实配置与当前原值。
2. 可复核的布尔谓词、公式、状态转移、排序或明确的不适用原因。
3. 有顺序的运行步骤，以及每个输出的实际消费者。
4. 参数的直接影响、下游影响、设计代价与证据状态。
5. `from → to`、缺失证明、影响和下一探针组成的结构化未知边。

字段值已确认但运行时语义未知时，两者必须分开定级；Priority、CoolTime、Enable 等名称不能单独证明参数处于资格、选择或调度阶段。

## 交付能力

正式 `complete` 模式同时生成：

- 从普通语言系统地图逐层下钻到真实文件和字段的 WebBook。
- 使用稳定 ID、原子断言、资产关系、运行时方法与证据路径的 Agent Knowledge Base。
- `llms.txt`、OpenAPI 3.1、只读 HTTP API 与本地 stdio MCP。
- 工作流、种子、Wiki、知识库、浏览器与发布边界的自动校验。
- 可选的本地经验队列和用户授权后的 Notion 同步；内部审查与专有原始内容不得上传。

## 安装

```bash
npx skills add blackplume233/game-developers-skills --skill game-deconstruction -g -y
```

安装后可直接要求 Agent “使用 game-deconstruction 拆解 `[游戏]` 的 `[系统]`”。只有游戏名称、没有可访问资产时，技能会先交付工具与解包准备方案，不会编造实现细节。
