# 角色技能锻造器

把一次性的“画得像”沉淀成另一个 Agent 能稳定复用、能解释依据、能停止错误迭代的角色专属知识漫画 Skill。默认目标路径为 `skills/content-creation/<character-slug>-knowledge-comic/`；用户指定其他能力或位置时，保留本技能的角色研究门槛，再调整目标输出契约。

## 工作边界

- 只使用用户提供或明确授权获取的图像。需要下载时，先确认授权，再优先使用官方/第一方页面或其媒体 CDN。
- 参考图只进入当前任务的本地分析目录；默认不复制进公开 Skill、Git 仓库或交付包。
- 单张图只能证明该视角可见的特征。背面、遮挡区域、材质细节和未出现的表情必须标为 `unknown`，不能包装成已确认事实。
- 将官方设定、社区共识、图像观察、合理推断和创作默认值分层记录，不能把后两者写成官方事实。
- 不把呆猫的固定脸、球形圆手、软织物材质推广为通用规则。每个角色都必须重新判定自己的脸部、肢体和渲染策略。
- “巡回学习”指参考图驱动的视觉比较、提示词修订和 Skill 约束沉淀，不代表训练、微调或持续修改底层模型。
- 创建、安装、提交和推送是不同授权。完成本地 Skill 不等于获准安装、提交或发布。

## 输入契约

最低输入是一张角色参考图和“要做成角色技能”的意图。合理默认：

- `capability`: `knowledge-comic`
- `language`: `zh-CN`
- `audience`: `普通成年人`
- `reference_policy`: `只用用户提供的图；下载需单独授权`
- `calibration_budget`: `最多 4 轮单变量修订`
- `pilot`: `一张无文字角色校准稿 + 一张九宫格动作压力测试 + 一个四格知识漫画试例`

仅当角色名称、权利边界或目标能力无法从上下文安全推断时才提问；版式、文件名和普通视觉参数采用默认值继续推进。

## 路由资源

- 开始研究和生成时，完整读取 [workflow.md](references/workflow.md)。
- 写目标 Skill 前，完整读取 [target-skill-contract.md](references/target-skill-contract.md)。
- 进行九宫格、自审或决定是否停止迭代时，完整读取 [evaluation-rubric.md](references/evaluation-rubric.md)。
- 用 [character-study.yaml](assets/templates/character-study.yaml) 保存证据、未知项和每轮校准结果；它是研究记录，不是要原样发布的角色圣经。

## 核心工作流

### 1. 建立证据台账

记录每张参考图的来源、授权方式、像素尺寸、视角、日期和可观察范围。先建立五层证据：

1. `official`: 官方/第一方明确陈述。
2. `community`: 多个可靠社区来源稳定一致的称呼或习惯。
3. `observed`: 从当前参考图直接可见。
4. `inferred`: 为连接可见信息所做的可撤销推断。
5. `creative_default`: 为生成内容主动设计的默认值。

目标 Skill 中所有身份硬约束必须能回指 `official` 或 `observed`；推断和创作默认不得伪装成事实。

### 2. 构建四类角色锁

使用视觉能力同时比较全部参考图，形成：

- `Identity Anchors`：轮廓、色块、标志部件、比例和不可丢失的识别特征。
- `Expression Policy`：从 `fixed | bounded | expressive` 三者中选择，并说明允许变化的眼、眉、嘴、朝向和外围特效。
- `Anatomy Lock`：头身比例、手足/爪/翼/触手拓扑、可见关节、抓握方式和动作触达机制。
- `Render Lock`：2D/3D、线条、材质、表面纹理、光照、色彩和必须避免的风格漂移。

如果能力不足以看图，仍可建立待确认骨架，但必须标注未完成视觉核验，不得声称角色相似度通过。

### 3. 校准而不是随机抽卡

先生成一张单角色、全身、无遮挡、无文字的轻动作锚点图。身份未通过时不做九宫格。锚点通过后生成九宫格压力测试，覆盖轮廓、动作拓扑、表情策略和渲染环境。

修订顺序固定为：

1. 身份与色块。
2. 脸部策略与肢体拓扑。
3. 比例与材质渲染。
4. 动作神韵、道具和外围特效。

每轮只改变一个变量，同时重复全部已通过硬约束。默认最多 4 轮；同一维度连续两轮没有可见改善就停止。保存问题、唯一改动、前后分数、采用结果和剩余偏差。

### 4. 提炼角色声音

分别记录官方台词、社区稳定口癖和本 Skill 原创句式。没有可靠声音证据时，为教学用途设计原创语气，并明确标为 `creative_default`。角色的可爱、威严或笨拙不能以讲错知识为代价。

### 5. 生成目标 Skill

若环境中提供 `skill-creator`，写文件前完整读取并遵循它；否则按 [target-skill-contract.md](references/target-skill-contract.md) 直接创建。新 Skill 首版使用 `1.0.0`，文件夹名与 frontmatter `name` 一致。

目标 Skill 必须把研究结论转成可执行决策，而不是堆砌形容词。至少包含：

- 图像来源与权利边界。
- 角色圣经及四类角色锁。
- 知识核实、教学脚本、绘图与后期文字分层流程。
- 单角色锚点、九宫格和真实任务校准规则。
- 有限迭代、停止条件和失败披露。
- 角色声音、质量清单、需求模板和包完整性校验。

运行：

```bash
python scripts/validate_character_skill.py <目标技能目录>
```

脚本只验证结构和部分显式契约，不能代替语义级视觉审查、隐私审计或权利判断。

### 6. 真实任务前向测试

用目标 Skill 完成一个小型但完整的四格知识漫画试例：核实一个低风险知识点，生成角色锚点、九宫格、分镜和至少一张试制图。测试输入不得泄露预期答案或刻意提示已知缺陷。

只有以下条件全部满足才判定完成：

- 身份、脸部策略和肢体拓扑均达到阻塞门槛。
- 角色在不同动作中仍可识别，且未靠错误五官或人体结构表达情绪。
- 材质与画风没有压过角色身份。
- 知识正确、文字后期分层、来源可追溯。
- 目标 Skill 能由另一个 Agent 按文档复现，不依赖本次对话中的隐含记忆。

## 提示词结构

每次生成使用四段式提示词，并在修订时只改对应段：

```text
[Identity Lock] 身份、轮廓、色块、标志部件、比例
[Expression + Anatomy] 脸部变化边界、肢体拓扑、动作触达机制
[Action + Intent] 当前认真想完成什么、重心、道具与构图
[Render Lock + Negative] 目标媒介、材质、光照及明确禁止漂移
```

不要使用“更像原图”“更有神韵”“更可爱”等无法定位变量的修订语句。

## 输出契约

完成后交付：

1. 目标 Skill 路径与版本。
2. 证据台账摘要及仍未知的视角/结构。
3. 四类角色锁与关键负面约束。
4. 锚点图、九宫格和试例的本地路径或能力声明。
5. 每轮单变量校准记录及停止原因。
6. 结构验证与人工语义审查结果。
7. 尚未执行的安装、提交或发布动作。

## 禁止做法

- 不要从一张正面图捏造完整三视图并称为官方设定。
- 不要照抄呆猫的固定脸、球形手和渲染词到其他角色。
- 不要用上一版生成图覆盖原始参考图的优先级。
- 不要同时修改身份、动作、材质和背景后宣称找到了原因。
- 不要把无穷重生成当优化；达到预算或无改善条件就停止并报告。
- 不要把参考图、下载截图、生成中间稿或用户私有素材提交进目标 Skill。
- 不要在未获授权时安装到全局、提交 Git 或推送远端。
