# 角色技能锻造工作流

本流程把参考图研究、视觉校准和 Skill 工程分开，避免“先写一大段提示词，再靠随机重生成碰运气”。

## 阶段 0：定义目标

先写一行目标：

```text
把 {角色} 锻造成能稳定完成 {知识漫画/用户指定能力} 的可安装 Skill；
在 {允许的表情、动作和环境} 中保持身份，并诚实披露未知项。
```

确定：角色名称、目标 slug、能力、语言、受众、公开/私用、允许使用的参考来源、是否允许下载、图像生成预算和输出位置。

默认目标是中文知识漫画。若用户只要一张图，停止本技能并改用普通图像生成流程；不要为一次性任务制造 Skill。

## 阶段 1：参考图清点

为每张图记录：

| 字段 | 含义 |
|---|---|
| id | 稳定编号，不使用含个人信息的文件名 |
| source | 用户提供、官方页面、第一方 CDN 或其他已授权来源 |
| rights | 用户授权范围或公开页面用途 |
| dimensions | 像素尺寸 |
| view | 正面、侧面、背面、近景、动作、互动、未知 |
| visible | 能直接确认的结构 |
| hidden | 被遮挡或画面外结构 |
| date | 获取/核实日期 |

下载前必须得到授权。只把图放在任务本地分析目录，不把引用图当作 Skill 资产分发。

### 最低证据充足度

- 一张清晰正面全身图：可开始，但只能建立正面可见的初版锁。
- 正面 + 三分之二侧面 + 面部近景：可校准主要身份与表情策略。
- 再加背面 + 两种动作：可较可靠地建立肢体拓扑和背部结构。

资料不足不是失败；把未知项显式写入目标 Skill，防止后续 Agent 自信补全。

## 阶段 2：角色分解

### Identity Anchors

按以下顺序观察：

1. 远距离剪影与头身比。
2. 最大色块及其边界。
3. 面部开口、眼鼻口或屏幕图形。
4. 稳定服装、配件、尾翼、耳角等标志部件。
5. 动作时仍不改变的结构。

每条锚点注明 `official | observed | inferred | creative_default`。只有前两者可以成为“不可改变”的身份事实。

### Expression Policy

选择一种模式：

- `fixed`：脸像固定贴图或面罩；情绪主要由身体、道具、构图和外围特效表达。
- `bounded`：只允许参考图中可证明的一组表情；逐项列出眼、眉、嘴的允许组合。
- `expressive`：五官可连续变化，但仍锁定形状、位置范围、比例和角色特有的表演方式。

不能因为某次生成的表情“更可爱”就扩充允许范围。

### Anatomy Lock

定义：

- 头、躯干和附肢数量。
- 手部类型：球形、手套形、爪、蹄、人手、翼端、触手、隐藏或其他。
- 可见关节及禁止出现的关节。
- 角色如何抓、托、指、推、跳、飞或够到远处。
- 动作夸张的上限和必须保持的比例。

“做什么动作”不能隐含修改“身体由什么组成”。

### Render Lock

从参考图实际媒介出发，定义：

- 2D/3D、线稿/块面、透视与轮廓处理。
- 主材质和局部材质。
- 纹理尺度、粗糙度、反光、环境遮蔽和光照范围。
- 允许的背景复杂度。
- 容易漂移到的错误媒介或商业化通用风格。

## 阶段 3：视觉校准

### 3.1 单角色锚点

目标：全身、无遮挡、无文字、简单背景、一个轻动作。动作要暴露角色神韵，但不能遮挡身份结构。

先比较参考图与生成图，不和提示词想象比较。身份锚点失败时，不进入后续压力测试。

### 3.2 九宫格压力测试

九宫格用于诊断，不用于一次展示九种随机画风：

| 格 | 测试 |
|---|---|
| 1 | 最可靠视角的中性全身基准 |
| 2 | 已有证据支持的另一视角 |
| 3 | 缩小剪影与比例识别 |
| 4 | 托举/抱持，检查手足拓扑 |
| 5 | 推拉/触达，检查关节和身体位移 |
| 6 | 跳跃/奔跑，检查动态比例 |
| 7 | 低强度情绪，检查脸部策略 |
| 8 | 高强度情绪，检查外围特效与表情上限 |
| 9 | 改变环境或光照，检查色块与材质稳定 |

没有侧/背面证据时，不把相应视角作为相似度测试；可用第二个已知动作替代，并继续标注未知。

### 3.3 单变量修订

每轮记录：

```yaml
round: 1
dimension: identity | expression_anatomy | proportions_render | action_spirit
observed_failure: "可直接指出的差异"
change_only: "本轮唯一修改"
invariants_repeated: []
score_before: 0
score_after: 0
accepted: false
```

禁止使用“整体优化”“更像”“更高级”作为唯一修改。四轮后仍失败，或同一维度连续两轮没有可见改善时停止；请求缺失参考图或报告能力边界。

## 阶段 4：语言与教学能力

把角色声音分为：

- 官方有出处的短语和称呼。
- 多来源稳定的社区习惯。
- 为本 Skill 新写的教学句式。

为目标受众定义句长、术语密度、称呼频率和禁用语。知识正确性独立于角色扮演：事实、推断、类比、笑点和角色设定必须可分辨。

## 阶段 5：Skill 工程

按 `target-skill-contract.md` 创建目标目录。先写角色圣经和来源，再写 SKILL 主流程；这样主流程引用的是已确认约束，不会在写作中途偷偷发明角色。

目标 Skill 中的提示词必须按四段式分层：Identity、Expression + Anatomy、Action + Intent、Render + Negative。把在校准中证实有效的约束沉淀进去，删除无效果、互相冲突或只针对某张失败图的临时措辞。

## 阶段 6：前向测试与交付

选择一个低风险、能用两份可靠来源核实的知识点，执行完整四格试例。至少检查：

- 另一个 Agent 是否只读 Skill 就能复现流程。
- 角色在锚点、九宫格和漫画试例中是否保持同一身份。
- 表情与肢体是否遵守各自策略。
- 图片层是否无文字，中文是否由后期文字层完成。
- 失败是否会触发有限修订和停止，而不是无限重生成。

交付 Skill、研究摘要、校准记录、验证结果和未知项。安装、提交、发布均等待对应授权。
