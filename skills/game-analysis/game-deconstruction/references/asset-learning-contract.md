# 资产学习期策划解释契约

逐资产页面不是类型转储的美化版。读者打开任意资产时，首屏必须先回答策划最关心的三个问题，再进入文件身份、类型、字段、引用和哈希证据。

## 固定首屏顺序

1. **影响了什么功能**：说明这份资产直接改变哪类玩家可见行为、AI 资格、选择、动作协议或侧向约束；不得只写“属于某子系统”。
2. **怎么配置影响的**：只展示本资产实际出现的字段、引用或实例顺序，并同时给出当前原值、策划旋钮、可能影响和证据等级。
3. **在全局配置中的什么位置**：写出上游、本资产所在层和下游消费者；未闭合的连接使用虚线/“未知”，不得用目录名补调用边。
4. **本资产不负责什么**：明确它不直接决定的 Goal、Decision、动作、动画、渲染或调度结果。
5. 完成上述解释后，才展示文件身份、完整类型、逐实例字段、引用边、覆盖层、校验和哈希。

## 生成要求

- 资产页必须从当前 build 的解析结果确定性生成，不能手工维护数千份页面。
- 人类首屏和 Agent 记录必须共用同一份结构化 `learning_card`，至少包含：

```text
planning_impact
configuration_influence[] {
  field
  current_values[]
  occurrences
  sample_complete
  planning_control
  effect
  evidence_status
}
global_position {
  chain
  role
  does_not_decide
}
basis {
  asset_path
  dominant_types[]
  userdata_reference_count
}
```

- 精确字段规则优先；只能确认结构、不能确认语义时必须写“运行时语义未知”。
- 字段值必须保留 `实例 ID + 实例类型 + 被哪个字段引用` 的上下文；同名 `IsAND`、`Priority`、`Process` 等字段不能跨实例合并成一个无上下文结论。
- 汇总只展示代表值时必须同时写出现总数和展示数；关键动作节点、条件组和候选列表应尽量完整展示。
- 空壳、Catalog、Table、引用聚合器或无直接字段资产，应解释其索引、类型、顺序或引用作用，不能强行写成最终决策。
- 枚举名称、优先级公式、评分聚合、刷新周期、动画 Clip 和渲染结果没有运行时证据时不得自动补全。

## 交付 Gate

- 所有逐资产页均存在上述三段首屏，并且出现在文件身份和字段转储之前。
- 每页至少包含一个实际字段影响；无字段时必须给出明确的无字段/引用型说明。
- `file-analysis.jsonl` 或等价机器索引为每项资产保存同源 `learning_card`。
- Agent KB 的每个 `asset` 记录包含策划功能、配置影响和全局位置，关键词检索可直接命中这些内容。
- 抽查主链上的 Situation、Goal、Decision、ActionInterface 资产，确认首屏解释能从字段回到真实配置，且未把未知写成事实。
