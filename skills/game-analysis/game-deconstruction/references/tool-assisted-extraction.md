# 白盒工具发现与解包方案设计

## 目标

把“找到游戏安装”推进为可复验的白盒资产证据链：识别格式、发现工具、设计解包方式、可信获取、隔离提取、结构解析、依赖追踪和双重验证。原安装始终是只读输入，不是工具工作目录。没有真实条目、提取物和字段/引用证据时，不得以运行现象或公开资料替代白盒结论。

## 工具发现顺序

1. 确认游戏、平台、build、引擎和归档头。
2. 优先查作者仓库、官方 release、引擎文档和工具源码。
3. 分别寻找：归档目录、选择性/全量解包、结构化资源解析、模型纹理动画预览和第二验证器。运行时对象检查只用于验证已取得的白盒证据。
4. 检查目标游戏和当前版本是否被明确支持；“支持同引擎”不能替代游戏级验证。
5. 记录仓库、release、commit、许可证、更新时间、下载 SHA-256、主程序签名、依赖和已知限制。
6. 拒绝来源不明附件、外部密钥、补丁 EXE、关闭安全软件或许可证/DRM 绕过。

工具评价优先级：当前版本兼容性 > 可选择性提取 > 只读能力 > 可审计源码 > 确定性输出 > GUI 易用性。

## 强制工具矩阵

在执行解包前输出工具矩阵；缺失的角色必须明确标记，不得默认由同一个工具可靠覆盖：

| 角色 | 必须回答的问题 | 最低验证 |
|---|---|---|
| 目录器 | 能否列出当前 build 的条目、层、压缩与路径状态 | 列目录成功，条目数稳定 |
| 解包器 | 能否只读、选择性或全量提取目标条目 | 单文件重复提取哈希一致 |
| 结构解析器 | 能否读取目标格式的类型、字段和引用 | 一个代表文件成功导出结构 |
| 领域预览器 | 能否验证模型、纹理、动画、图或表的语义 | 与结构解析结果路径/ID 对应 |
| 第二验证器 | 如何验证关键字段没有被错误解释 | 第二工具、源码结构或运行时对象一致 |

每个候选记录：名称、用途、仓库/官方页、release、commit、许可证、目标游戏/build 支持证据、下载 SHA-256、主程序签名、依赖、读写行为、已知限制和弃用原因。

## 解包策略决策

| 策略 | 适用条件 | 必须产出 |
|---|---|---|
| 目录优先 | 未知格式、首轮侦察、空间不足 | 完整条目目录、层信息、未知条目统计 |
| 定向提取 | 已有路径表、类型或领域关键词；默认选择 | 选择规则、焦点提取物、逐文件清单与哈希 |
| 全量解包 | 用户需要完整资产库，且工具/空间/时间均验证通过 | 分层输出、全量清单、失败与未知条目 |
| 解析器直读 | 解析器可从容器流式读取条目 | 容器目录、焦点资产导出、解析结构与哈希 |

不要把“全量解包”机械地视为更白盒。可追溯的定向提取加结构解析通常比无索引的海量文件更有分析价值。

## 解包方案必填项

执行前生成方案并写入案例目录，至少包括：

1. 游戏、平台、app/build、归档格式和归档集合。
2. 原始输入路径、只读/副本策略、源文件前后校验方式。
3. 基础包、DLC、语言包和补丁包的优先级及删除/覆盖语义。
4. 工具链、固定版本、来源、哈希、许可证和各工具职责。
5. 路径表/哈希表来源、版本、未知名称的保留方式。
6. 选择目录优先、定向提取、全量解包或解析器直读的理由。
7. 领域筛选规则、预计条目数、预计输出体积和可用空间。
8. 输入、输出、命令、日志、manifest 和临时文件位置。
9. 重复提取、第二解析器、字段抽样和活动视图的验证方式。
10. 停止条件、失败后的下一候选工具以及删除案例目录即可完成的回滚方式。

## 案例目录

```text
[case]/
├── case/                 # build、清单、源元数据
├── tools/                # 工具来源、版本、哈希，不放专有资产
├── catalogs/             # PAK 条目、路径表、未知哈希
├── layers/               # base、patch_001...分别保存
├── active-view/          # 最高优先级逻辑视图或索引
├── focus/
│   ├── ai/
│   ├── skills/
│   ├── animation/
│   └── rendering/
├── reports/
└── logs/
```

全量副本与全量解包可能需要源大小数倍的空间。先估算空间，默认只做目录和定向提取。空间足够时优先分析普通副本；空间不足时，只允许已验证的只读工具读取原归档并把全部输出写到案例目录。不要使用指向原安装的硬链接作为可写工具输入。

## 提取阶段

### A. 快照

记录所有源文件的路径、大小、时间、版本和可行时的 SHA-256。至少记录归档头、PAK 数量、基础包/补丁包命名和工具运行前后源文件大小/时间不变。

### B. 目录化

使用游戏对应路径表解析已知哈希；未知条目必须保留。统计根目录、扩展名、大小、压缩方式和覆盖层。路径表是候选目录，不等于文件在当前 build 一定存在。

### C. 定向提取

按领域路径、扩展名和关键词筛选，先提取数十到数百个高价值文件。每个输出记录源 PAK、层级、资源路径、大小、SHA-256、工具版本和提取时间。

### D. 分层合并

基础包和每个补丁包单独提取。活动资源定义为同一路径中优先级最高的有效版本；仍保留所有旧层及覆盖关系，避免把版本变化抹掉。

### E. 结构解析

使用适配格式的解析器读取字段、类型、GUID、ObjectID、资源路径和引用。关键配置至少用第二解析器、运行时对象或重复提取哈希验证一次。

### F. 引用图与白盒模型

以逻辑资源路径为节点，以字段中的资源路径、GUID、ObjectID、类型引用和补丁覆盖为边，建立领域引用图。每个系统结论必须回指：源 PAK/层、资源路径、文件哈希、解析器版本、实例类型、字段或引用目标。

### G. 可复现验证

用同一输入、固定工具版本和相同选择规则重复执行焦点提取。比较输出文件集合、逐文件 SHA-256、解析 JSON 的规范化差异及警告。任何解析器版本不匹配、未知条目、CRC/类型表差异都写入结果，不得静默忽略。

## 可执行文件静态还原

当资产已经证明“配置了什么”，但用户还要学习“运行时怎样消费配置”时，再进入可执行文件静态分析。只允许读取用户合法持有的本地二进制；不启动目标、不注入、不附加、不修改内存，不绕过 DRM、完整性校验、许可证或联网服务。

按以下顺序执行：

1. **固定二进制身份**：记录平台/build、文件版本、大小、SHA-256、签名、PE/ELF/Mach-O 结构、调试记录和异常/函数边界数量。地址结论只适用于相同哈希。
2. **识别元数据模型**：优先从官方文档、公开引擎源码或可审计工具源码确认反射/类型数据库版本、ID 位宽和记录布局；不要只凭相邻字符串猜结构。
3. **解析完整签名**：恢复类型、方法名、参数、返回值、方法索引和元数据地址，并用资产类型/字段生成少量高价值方法种子。
4. **寻找调度连接**：按结构不变量识别 invoke/dispatch 表，例如空首项、连续可执行地址、同族 wrapper；不要仅凭“看起来像函数指针”选表。
5. **先读初始化代码**：若磁盘方法偏移为零或名字没有代码 XREF，检查启动时的相对指针修复、类型登记表、方法补丁表和统一函数基址。反射字符串无直接 XREF 不代表实现不存在。
6. **建立可追溯映射**：保存 `方法索引 → 完整签名 → 登记项 → 原生目标地址 → 函数边界/伪代码`，并标明每一跳的来源。
7. **只做定向反编译**：先反编译与已闭合资产链直接相关的方法簇；用第二反汇编器复核关键算术、短路分支、尾跳转和异常短函数。
8. **与资产交叉验证**：只有签名、字段偏移、控制流和已解析资产结构互相支持时，才给出业务语义；教学变量名、状态名和推测字段必须显式标注。
9. **输出恢复边界**：始终称为伪代码/控制流级还原，不声称获得原始源码、原变量名、注释或逐字一致实现。

需要保留的最小证据：二进制身份 JSON、元数据表摘要、方法种子、目标地址表、工具版本/哈希、定向反编译输出、关键函数的指令级复核、面向读者的事实/推断/未知表。

遇到以下情况停止该路径并记录原因：分析开始触及保护绕过；目标地址只能通过执行/解密保护段取得；登记表与指令边界冲突；静态映射落入明显无关的短导出；或不同工具对关键算术给出矛盾结果。可继续研究未受保护的元数据、资产和普通初始化逻辑，但不得为了“还原完整源码”越过边界。

## 领域路由

### AI

搜索 `ai`、`behavior`、`decision`、`goal`、`situation`、`sensor`、`personality`、`formation`、`target`、`threat`、`nav`、`waypoint`、`fsm`。关注行为/状态资源、角色参数、目标规划、感知形状、空间数据、动作接口和队形。

### 技能与战斗

搜索 `skill`、`ability`、`action`、`attack`、`damage`、`hit`、`status`、`cooldown`、`cost`、`range`、`job`。建立“职业/角色 → 技能定义 → 动作状态 → 动画 → 判定/效果 → VFX”引用链。

### 动画

搜索 motion、FSM、motlist/motbank、clip、timeline、rig、skeleton、retarget、chain。记录动画 ID、骨架、时长、循环、事件、Root Motion、状态转换及技能引用。

### 渲染

搜索 mesh、material/MDF、texture、shader、render config、effect、light、probe、LOD、streaming。记录模型—材质—纹理—着色参数—特效依赖和平台/质量分支。

## RE Engine 路线

优先评估持续维护且明确支持目标游戏的 PAK/RSZ 工具。REasy 可用于 PAK 浏览、选择性提取和 SCN/PFB/User、UVAR、MOTBANK、MESH、TEX、MDF 等格式；RE_RSZ 可交叉检查 RSZ/FSM；REFramework 只放在离线解析之后验证已取得的对象类型和字段，不属于首轮解包工具。

`reasy_selective_extract.py` 不包含或复制第三方解包算法，只导入用户已获取的 REasy 源码并编排只读选择性提取。`reasy_rsz_dump.py` 使用同一源码与目标游戏 RSZ dump，将实例类型和字段导出为审阅用 JSON。第三方工具的许可证、兼容性和输出正确性仍需单独验证。

## 停止条件

- 输出目录位于游戏安装内。
- 工具尝试写回、重打包或注入，而当前阶段只授权离线提取。
- 工具要求外部密钥、破解补丁、账号/许可证绕过或关闭安全软件。
- 当前 build 无法识别，或解析器间对关键字段严重冲突。
- 源文件大小/时间/哈希在工具运行后改变。
- 空间不足或输出规模失控。

停止某个工具路径不等于停止白盒任务；保留日志并换第二工具、固定源码版本、公开格式实现或最小只读解析器。所有可行工具路线都失败时，输出“白盒拆解受阻”和所需下一输入，不得把黑盒观察包装成拆解完成。
