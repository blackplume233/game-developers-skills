# 拆解学习 Wiki 交付规范

当用户要求网页、知识库、知识图、可缩放地图或完整教学 Project 时读取本文件。目标是让读者从“这套方案是什么”逐层走到“哪个文件、哪个字段支持它”，而不是把全部节点塞进一张可缩放画布。

## 信息层级

按以下层级组织内容，每层都能返回上层并进入下一层：

1. **方案总览**：一句话模型、系统边界、核心运行链和最重要结论。
2. **子系统**：职责、输入、输出、主要配置族和相互关系。
3. **运行环节**：状态、顺序、条件、失败分支和跨系统接口。
4. **配置实例**：真实资产路径、类型、字段、引用、覆盖层和置信度。
5. **原始证据**：解析 JSON、字段转储、哈希、日志或源文件查看器。

页面先回答“它是什么、为什么存在、在整条链的哪里”，再展示参数与证据。不要让读者从文件列表反推系统总图。

## 书名、封面与行业入口

完整 Book 的书名是知识契约。标题直接写明游戏与工程对象，例如 AI 配置、行为选择、动画状态或渲染管线；副标题再说明白盒证据、贯穿案例或学习结果。文学化场景名、角色台词和悬念句可以进入案例章节，不能让它们代替全书主题。

封面必须让第一次接触目标游戏的策划或程序在五秒内回答四个问题：研究哪款游戏的什么系统，使用什么证据，贯穿案例是什么，读完能完成哪类工程任务。解包文件数、对象数和方法数放在次级证据区，不能抢占主标题和学习承诺。

导论先借行业通用职责建立地图，例如“世界提供什么信息 → 哪类问题值得处理 → 谁能执行 → 怎样选择办法 → 动作如何推进 → 表现和效果怎样接入”。随后再映射目标游戏的专名、资产族、字段和运行时方法。外部 GDC 分享、官方文档和业内教材只用于安排教学顺序，不能替代当前 build 的本地证据。

初稿完成后先用自然中文写作 Skill 做成稿修订，再让未参与写作、不了解目标游戏专名的 SubAgent 冷读书名、封面、导论和目录。冷读 Gate 至少检查：五秒内能否识别知识主题，能否用普通话复述系统地图，章节标题能否独立说明工程职责，封面承诺是否超出证据。阻断项关闭后再进入费曼事实与证据审查。

## 默认开篇：用一个角色案例画完整 Graph

完整报告或 WebBook 的默认入口不从子系统术语、文件统计或字段表开场。先选择当前 build 中证据最完整的一名队友、怪物、技能或交互实例，用一张完整 Graph 回答“它为什么会做出这个行为”：

1. 主链从运行输入开始，依次展示判断、待办/意图、候选选择、动作步骤、运行执行和表现输出；没有证据的环节保留断点。
2. 主节点标题只用零基础读者能复述的普通语言。游戏专名第一次出现时就地给一句定义；领域术语、类型名和字段名只能出现在节点展开层或后续章节。
3. 每个配置节点至少列出一份真实资产，并解释“这份资产干什么、能配置什么、不负责什么、位于全局链哪里”，提供源文件入口。
4. 多份资产共同完成一个环节时，必须显示数量和分工；禁止用单一虚构的“角色 AI 文件”概括跨文件配置。
5. 感知、性格、队形、空间标记等旁路系统若确实存在但未闭合到案例，用虚线侧向输入表示并明确写出证据边界。
6. 已确认的静态引用、已恢复的运行时消费、工程解释和未知连接使用不同线型或状态标记；每一段边自己携带证据语义，禁止用一条贯穿全图的“已确认”底线覆盖未闭合输入和输出。
7. Graph 使用 DOM 与矢量图标保持文字清晰；展开内容在触发点附近显示并自动进入当前视野，窄屏改为纵向信息层而非横向丢失或整体缩小。
8. 通用执行器具备切换、中断或收尾能力，不等于当前案例在失败、死亡或取消后必然走同一恢复协议；案例行为没有闭合时仍标未知。

开篇 Graph 负责建立全局心智模型，正文继续承担完整解释；两者必须使用同一案例、同一证据状态和同一资产路径。

核心领域术语页面还必须完整读取并遵循 [concept-teaching-contract.md](concept-teaching-contract.md)：首屏先给通俗定义和工程身份，再展示真实配置树；随后按输入、处理、输出、消费者和更新时机解释运行时，并单列“决定什么 / 不决定什么”。不能把类型名或字段列表本身当作定义。

进入配置实例和逐资产学习层时，还必须遵循 [asset-learning-contract.md](asset-learning-contract.md)：先展示“影响什么策划功能 → 哪些实际字段/引用如何影响 → 位于全局配置链哪里”，再展示文件元数据和完整字段。资产页不能把策划解释埋在数百行字段之后，也不能只复用子系统套话。

## Wiki 阅读结构

- 左侧提供稳定的知识树，中央显示当前文章，右侧提供本页目录或证据入口；窄屏时把两侧变成互斥抽屉。
- 默认入口必须是方案总览。页面标题、URL 和浏览器前进/后退应反映当前知识节点。
- 全局搜索同时覆盖已发布文档与资产索引；结果必须区分“教学页”和“源资产”。
- 每个重要结论提供可点击的源文件或解析证据入口；源文件查看器支持检索、相邻文件切换和对比。
- 图用于降低关系理解成本，正文承担完整解释。页面不能依赖一张大图才能阅读。

## 语义缩放

“缩放”表示信息密度随层级变化，而不是把整张图按比例缩小：

- 缩小时保留系统骨架、节点名称和当前焦点，隐藏次级字段，不缩小正文到不可读。
- 放大或展开节点时，在触发点附近展示下一层，并把新内容或其标题带入当前视野。
- 保持被选择节点的视觉锚点稳定；不得把展开内容生成在视口之外，让读者自行寻找。
- 使用清晰文本、矢量图标和分层页面；禁止用整体 CSS transform 或位图 Canvas 承担主要阅读界面。
- 为每层提供面包屑、返回上层和继续下钻入口，使读者知道当前位置。

## 图标与视觉引导

- 图标必须表达稳定语义，例如总览、流程、决策、动作、文件、证据、搜索和警告。
- 相同语义始终使用同一图标，并保留文字标签；不得让图标成为唯一信息载体。
- 优先使用随 Project 一起交付的 SVG 图标与字体回退，避免网络资源失败导致空白或错位。
- 控制颜色、卡片和装饰数量，用层级、留白和排版建立重点。

## 多页面设计系统

Project 同时交付主 Book、资产学习器、证据查看器或对比工具时，完整读取并遵循 [delivery-design-system.md](delivery-design-system.md)。主 Book 是视觉真源；所有读者入口共享设计令牌、字体栈、语义状态色和本地 SVG sprite。工具页可以使用适合检索与核验的布局，也可以为 JSON、Hex、Diff 保留深色证据表面，但必须通过设计系统清单登记并完成真实浏览器回归。

## 发布边界

读者内容与生成过程必须物理分离：

- `docs/` 或等价发布目录只保存面向读者的课程与说明；公开证据区与内部审查区不是同一概念。
- 独立费曼审查、生成日志、评分、Verdict 和阻塞项只保存到专用 `.internal/reviews/` 或不可发布的 Goal 审计区。
- Wiki 清单采用发布页白名单；导航、面包屑、相关文章、搜索、站点地图、下载接口、通用文件 API、页面 API 与构建产物都只能读取白名单内容。
- 服务端对 `.internal/` 设置显式拒绝；内部审查不得从教学正文链接，也不得通过正常路径、URL 编码、大小写变体或猜测旧路径访问。
- 可以在最终交付说明中陈述“已完成内部验证”，但不展示审查过程、SubAgent 身份、评分或 Verdict 页面。
- `/api/wiki/page` 或等价页面接口必须逐页检查发布 manifest 白名单；允许 `docs/`、`book/` 目录并不代表目录下全部文件可发布。
- 需要 Agent 访问时完整读取 [agent-access-delivery.md](agent-access-delivery.md)，让 llms、OpenAPI、HTTP 和 MCP 共享 AKB 证据契约。

## 启动与回归门槛

交付前至少验证：

1. 默认 URL 返回非空页面，静态资源 MIME 正确，浏览器无脚本错误。
2. 清单中的每个页面存在，默认页属于清单，所有内部目录都不在清单或构建产物中。
3. 导航切页、浏览器前进/后退、全局搜索、源文件跳转和窄屏抽屉可用。
4. 页面文本在常用缩放级别仍清晰；主文章没有整体 transform 缩放。
5. 节点展开后，新标题或内容进入当前视野，焦点不会无提示跳走。
6. 内部审查的正常路径、编码路径与大小写变体返回 403/404；页面 DOM、源文件、搜索结果和网络响应都不包含闭卷自测、答案区、审查过程或 SubAgent Verdict。
7. 若服务在内存中缓存清单，修改清单后必须重启并重新验证实际监听实例。
8. 默认页 Graph 至少包含一条完整单角色案例主链；主节点普通话优先，配置节点可进入真实资产，旁路与未知边不冒充已确认连接，窄屏不水平丢失。

可先运行静态门禁：

```powershell
python skills/game-deconstruction/scripts/validate_learning_wiki.py `
  --project-root [Project根目录] `
  --content-root [Wiki文档根目录] `
  --manifest [Wiki清单JSON] `
  --web-root [公开Web根目录] `
  --design-manifest [设计系统清单JSON]
```

静态门禁不能替代真实浏览器测试；它负责提前发现路径越界、缺页、默认页错误和内部审查泄露。
