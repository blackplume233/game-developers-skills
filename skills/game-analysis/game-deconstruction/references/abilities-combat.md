# 技能与战斗系统拆解维度

## 分析目标

建立“输入/AI 请求 → 激活校验 → 目标选择 → 执行阶段 → 效果结算 → 表现与反馈 → 结束/冷却”的端到端模型，并识别数据驱动配置方式。

## 技能目录

先保留原始资产名、逻辑路径、技能 ID、类型和来源层，再增加职责分类：

- 移动、攻击、防御、控制、增益、减益、召唤、交互、被动和系统技能。
- 玩家技能、AI 技能、武器动作、环境能力和剧情脚本能力。
- 主动、被动、触发、持续、引导、蓄力、连段和反应技能。

记录每个技能的来源角色、输入、前置条件、阶段、目标、成本、冷却、效果、表现资源、取消规则和网络权限。

## 配置模型

检查是否存在以下概念及其组合方式：

- 技能定义与运行时实例。
- 标签、类型、阵营、武器和姿态限制。
- 属性、资源、等级、成长曲线和数值表。
- 效果规格：修改值、持续时间、周期、叠层、免疫、驱散和来源快照。
- 目标策略：自身、锁定、区域、射线、投射物、链式、智能选择。
- 表现引用：动画、VFX、SFX、镜头、UI、震动和材质参数。
- 继承、模板、组件、数据表或节点图等复用关系。

不要因为多个技能共享视觉效果就断言它们共享逻辑定义；分别验证逻辑、数值和表现的解耦程度。

## 生命周期与时序

拆解以下时间点：

1. 请求与本地预输入。
2. 条件校验和资源承诺。
3. 前摇、激活、命中窗口、持续、后摇和恢复。
4. 目标确认、碰撞/射线/投射物判定。
5. 伤害、状态、位移和标签变更。
6. 动画事件、VFX、SFX、镜头和 UI 反馈。
7. 打断、取消、连段分支、失败和冷却开始。

从时间轴、Montage/Clip、Notify/Event、碰撞和效果字段建立时序；运行逐帧只用于验证这些字段的运行语义，不默认三者完全一致。

## 战斗规则

- 伤害公式、护甲、抗性、暴击、弱点、部位和难度修正。
- 硬直、韧性、格挡、招架、无敌帧、霸体、击退和处决阈值。
- 命中停顿、镜头、音画反馈与数值结算的先后关系。
- 连段窗口、输入缓存、动作取消、目标吸附和转向修正。
- 资源循环、技能轮转、风险回报和敌我交互。

## AI、动画与网络关系

- AI 根据距离、效用、标签、资源、冷却和战术槽位如何选技能。
- 技能如何请求动画状态、蒙太奇、Root Motion、移动锁定和事件帧。
- 动画事件是权威逻辑、表现通知还是两者的桥接点。
- 联机时谁拥有激活、目标、命中和效果的最终权威；预测失败如何回滚或校正。

## 白盒提取与验证

- 追踪 `输入/AI selector → grant/loadout → skill definition → tags/条件 → cost/cooldown → targeting → effect → attribute/curve`。
- 追踪 `skill → phase/section/notify → collision/hit → animation/VFX/SFX/UI`。
- 导出技能 ID、父类/模板、标签、成本、冷却、目标形状、伤害/状态、叠层、阶段和表现引用字段。
- 对公式表、曲线、效果对象和补丁覆盖做字段级比较；保留动态计算或服务端覆盖的未知项。
- 实机取消、叠层和网络测试只验证序列化字段，不替代配置解析。

## 输出结构

1. 技能分类表与配置字段字典。
2. 单技能生命周期时序图。
3. 伤害/效果计算链与状态交互矩阵。
4. 动画、AI、输入、网络和表现依赖图。
5. 可复刻的最小技能框架与测试用例。
6. 未知项、替代解释和验证实验。
