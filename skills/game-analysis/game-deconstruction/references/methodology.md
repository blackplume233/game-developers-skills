# 证据与验证方法

## 1. 定义问题

把宽泛目标改写为可从资产结构回答的问题：

- 不问“AI 怎么做的”，改问“敌人如何发现目标、选择行为、共享信息并退出战斗”。
- 不问“技能怎么配”，改问“技能的触发条件、阶段、成本、效果、事件和取消规则如何组合”。
- 不问“动画有哪些”，改问“哪些动画承担移动、战斗、反馈和过渡职责，它们如何被状态与事件驱动”。
- 不问“渲染怎么实现”，改问“哪些视觉特征需要哪些渲染阶段、数据与性能取舍”。

## 2. 证据等级

按可靠性记录，不用等级替代具体来源：

| 等级 | 典型来源 | 使用方式 |
|---|---|---|
| E0 | 已授权源码、编辑器配置、真实提取资产、解析字段与资源引用 | 可支持实现级事实，但仍需记录 build、源层、文件哈希和解析器版本 |
| E1 | 可重复解包结果、第二解析器结果、运行时对象、日志或性能捕获 | 用于验证 E0 结构的稳定性与运行语义 |
| E2 | 开发者演讲、官方文档、补丁说明、招聘技术描述 | 可支持架构线索，注意发布时间与版本 |
| E3 | 未经独立复验的社区工具输出、可信技术分析、二手采访 | 用作工具候选或交叉验证，不单独支撑白盒结论 |
| E4 | 类似项目经验、视觉特征、引擎惯例 | 只能形成待验证假设 |

## 3. 结论状态

对报告中的关键陈述使用以下标签：

- `事实`：由 E0 直接支持。
- `观察`：由可重复的 E1 结果支持，但没有直接字段或源码结构。
- `推断`：由多个线索形成的最佳解释，必须给出替代解释。
- `未知`：当前资料不能区分的实现。

置信度使用 `高/中/低`，同时说明原因。例如：“中：三次可重复观察一致，但没有配置或运行时数据。”

## 4. 证据台账字段

每条证据至少记录：

- 编号、材料类型、来源或本地路径。
- 游戏 build、平台、归档、基础包/补丁层和逻辑资源路径。
- 源文件与提取物 SHA-256、解析器版本、类型、实例和字段/引用位置。
- 直接解析到的内容，不混入解释。
- 支持/反驳的假设。
- 证据等级、许可限制和复现步骤。

## 5. 假设卡

为高价值推断记录：

1. 假设：一句可证伪的陈述。
2. 依据：关联证据编号。
3. 替代解释：至少一个同样可能的机制。
4. 预测：若假设成立，在新场景下应出现什么。
5. 验证：换解析器、换资源版本或只改变一个主要变量。
6. 反例条件：出现什么就需要放弃或修改假设。
7. 当前状态：未测、部分支持、支持、反驳。

## 6. 白盒复验设计

- 固定游戏 build、源 PAK 集合、路径表、工具 release/commit 和解析类型表。
- 对同一选择规则重复提取，比较输出集合与逐文件 SHA-256。
- 用第二解析器、公开结构定义或运行时对象复验关键类型、字段和引用。
- 分别保留基础包与补丁层，比较同路径资源的字段级差异，不只比较文件时间。
- 对引用链执行闭合检查：资源路径、GUID、ObjectID 或实例引用必须能解析到目标或明确标为缺失。
- 抽样检查未知哈希、解析警告、CRC/类型表不匹配和损坏条目，不静默排除失败样本。
- 如需运行游戏确认字段语义，只验证已有白盒假设，并把运行结果与资产证据分栏记录。

## 7. 停止条件

只有达到 SKILL.md 的白盒完成门槛，且新增资产不再改变系统模型、关键引用链已闭合或明确断点、未知项已列出时，才停止继续收集。工具或格式受阻时输出受阻报告和下一解析路线，而不是用现象推测填满空白。
