# 多页面学习交付设计系统

当一个拆解 Project 同时包含 WebBook、资产学习器、证据查看器或对比工具时读取本文件。目标不是让所有页面长得完全一样，而是让读者明确感到它们属于同一本技术书、共享同一套信息语言。

## 设计原则

1. **指定视觉真源**：选择主 WebBook 或等价阅读入口作为排版、色彩、品牌和交互语气的基准。工具页可以保留不同布局，但不得另起一套品牌外壳。
2. **共享基础资产**：所有读者页面共享同一份设计令牌、字体栈、语义状态色和本地 SVG sprite。不要为每个页面复制颜色变量、字符图标或重新引入一套图标库。
3. **保持功能语义**：阅读外壳可以使用统一的浅色纸张语言；JSON、Hex、Diff、日志等机器证据面板可以使用深色表面，但必须说明用途，并与普通正文形成稳定、可辨认的层级关系。
4. **共享语义而非强制同布局**：Book 可以是章节阅读布局，资产学习器可以是检索—正文—Inspector 工作台。二者需要共享品牌、令牌和图标，不需要共享路由器或 DOM 结构。
5. **图标只做导航增强**：相同概念始终使用相同图标，图标旁保留文字标签；离线打开时图标仍可用。
6. **先保证阅读，再压缩工具密度**：正文保持舒适行长和清晰字号；窄屏优先让阅读内容进入视野，再把索引和 Inspector 变成堆叠区、抽屉或次级区域。

## 设计系统清单

完整 Web 交付复制 `assets/templates/delivery-design-system.json` 到公开 Web 根目录并填写：

- `visual_source`：视觉真源页面。
- `pages[]`：所有读者可访问的 HTML 入口及其功能角色。
- `shared_assets.tokens`：共享设计令牌样式表。
- `shared_assets.icons`：共享本地 SVG sprite。
- `evidence_surfaces[]`：允许保持深色或高密度的技术证据区域、用途和选择器。
- `responsive_viewports[]`：真实浏览器回归所覆盖的关键视口宽度。

清单只描述产品契约，不规定框架、类名、像素或具体实现。静态校验负责确认文件存在且被所有登记页面引用；真实浏览器负责确认视觉效果、布局和对比度。

## 浏览器 Gate

至少验证：

1. 从 Book 进入学习器、再返回 Book 时，品牌、字体、强调色、证据状态色和图标语义连续。
2. 每个登记页面都实际加载共享令牌与 SVG sprite，不依赖公网字体或图标才能完整显示。
3. 正文行宽与字号适合连续阅读；工具栏、索引和 Inspector 不挤压正文到不可读。
4. JSON、Hex、Diff 等登记证据面板具有足够对比度，但不会让整个工具页看起来像另一个产品。
5. 清单中的关键视口均完成真实浏览器测试；窄屏没有水平丢失主要内容，导航和返回路径仍可用。
6. 浏览器控制台没有资源 404、脚本错误或 SVG sprite 引用错误。

静态校验增加设计系统参数：

```powershell
python skills/game-deconstruction/scripts/validate_learning_wiki.py `
  --project-root [Project根目录] `
  --content-root [Wiki文档根目录] `
  --manifest [Wiki清单JSON] `
  --web-root [公开Web根目录] `
  --design-manifest [设计系统清单JSON]
```

静态通过不代表视觉通过。截图只能作为回归证据，不能替代对 DOM、计算样式、响应式布局、键盘导航和控制台错误的断言。
