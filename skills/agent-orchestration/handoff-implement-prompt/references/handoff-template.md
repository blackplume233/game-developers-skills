# Handoff 模板

模板只定义待填写栏目，不是额外执行授权。按目标项目规则使用；不适用项标为“不适用”或删去，不为凑齐栏目创建任务系统。删除占位说明，不复制正式契约。模板不依赖具体产品、任务或工作流框架。

## 元信息

- 任务、记录日期、当前阶段与下一阶段。
- 本次允许动作与尚未获准的后续动作。
- 已存在的 task / Issue / plan / 验收 / context 导航（按需）。
- 状态：仅研究、待实施、实现中、待验证或阻塞，不能混用。

## 目标与范围

- 用户确认的目标，必要时保留短原话，不复制整段聊天。
- In scope / Out of scope。
- 已选方案及理由；已否定方案只保留防止重走弯路的结论。

## 工作区与材料基线

- 已确认的工作区及写入边界；路径解析基准。
- 代码任务记录当前分支、HEAD、已核实 base；非代码任务记录资料版本或采集时间。未检查的值明确标注。
- 本任务改动与无关改动的区分。
- 工作区、分支和外部资料都是记录时快照，接手需刷新。

## 事实、设计与入口

- 已核实事实：准确文件、章节、符号或其他来源及其版本、新鲜度。
- 拟议设计：适用的依赖方向、接口、失败路径和影响范围。
- 未核验的假设与明确的验证动作。
- 下一阶段必读材料、精确位置及读取理由；不复制整篇规范或源码。

## 已完成与未完成

- 已完成的产物、实际更改与实际行为。
- 未开展、进行中与待验证内容。
- 项目要求但尚未满足的任务追踪或交付前置条件（如有）。
- 不把别人的改动当成本任务进度。

## 验证记录

| 检查 | 命令/入口 | 结果与材料快照 | 未覆盖范围 |
|---|---|---|---|
| 待填写 | 待填写 | PASS / FAIL / BLOCKED / NOT RUN，附证据 | 待填写 |

未执行的验证不得声明通过；运行成功与功能验收通过分别记录。不适用的构建或测试不要虚构。

## 阻塞、失败与纠正

- 可复现症状、根因或待验证假设。
- 做过什么、观察到什么、排除了什么。
- 当前阻塞及其恢复条件，不伪造授权或远端状态。
- 易混淆参数、路径、权限和生命周期语义的纠正结论。

## 下一阶段与验收

- 接手后第一项有用动作，不要求重新扫描全部材料。
- 按依赖排序的下一阶段步骤、退出条件与验收入口；不默认下一阶段必然是实现。
- 必须保留的邻近行为和负向断言。
- 暂停条件、需要用户决定的事项。
- 最终回报：更改/产物、实际检查、残余风险与阻塞。

## 恢复与保留

- 入口、正文、短提示词的实际路径和解析基准。
- 记录短提示词的组织及检查方式，不编造构建命令、元数据或 hash。
- 后续任务需要的真实构建/验证命令属于交接内容，不是生成本交接包的前置步骤。
- 区分持久材料与本机临时输出。若唯一正文也在临时目录，明确保留整个包的要求。
- 换 workspace 后重新核对路径、范围和状态；不复制父历史，也不自动启动后续任务。
